## 5. Reset

- [ ] 5.1 Add the `DemoState` singleton model and its migration. Verify: `python manage.py makemigrations --check` is clean after adding it, and `migrate` on an empty SQLite database creates the table.
- [ ] 5.2 Implement `perform_reset(force=False)` (D9): an `atomic()` transaction under `BEGIN IMMEDIATE`, the due re-check, deleting every tracking table except `DemoState` with no `flush` and no `sqlite_sequence` reset, loading the seed with explicit PKs inside `allow_seed_writes()`, ensuring the demo user exists, and setting `last_reset_at`. Verify: tests assert that after visitor activity only the seed rows remain, that a visitor item created after the reset gets a PK higher than any pre-reset visitor item, and that a stale visitor-item URL returns 404 while seed item URLs still resolve.
- [ ] 5.3 Implement history generation through the real pipeline with `ReplayFetcher(clock=d)` per simulated day, backdating `WebUpdate.timestamp`. - [ ] 5.4 Add the `demo_reset` management command (forced reset). Verify: running `DEMO_MODE=True python manage.py demo_reset` twice in a row succeeds both times and leaves exactly the seed data.
- [ ] 5.5 Implement `DemoResetMiddleware`: the due check (idle plus the activity write interval, and the minimum interval since the last reset), resetting before the view runs, and throttled `last_activity_at` writes.
